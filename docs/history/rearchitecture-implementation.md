## 実装

- application / infrastructure / presentation / workersの旧ソース構成を廃止し、core / integrations / desktop / hostへ再構築した。
- 型・契約・状態の所有者を機能別に整理し、Qt・外部通信・Rustから独立したcoreを実装した。
- セッションの制御キューと、各1系列の合成・再生パイプラインを実装した。キュー上限、停止、再開、初期化中の停止、古い結果の破棄を扱う。
- YouTubeとテスト送信を同じ計画・実行経路へ統合した。元コメントは表示用に保持する。
- 接続・再接続の通知を取得処理から受け取り、セッション状態へ反映する。
- 設定を編集ドラフトにし、話者取得と辞書インポートを専用Presenterから非同期で依頼する。
- 更新確認・話者取得の失敗を、その操作内で扱う。配信の停止には波及させない。
- 棒読みちゃんを外部送信の契約に分離し、疑似WAVを削除した。外部送信と実再生の完了を区別する。
- 固定の画面、グラフ、カード、プレースホルダーをDesignerフォームへ定義した。フォームの入れ子読み込みは外側の読み込み完了後に実施する。
- schema_version 2、エンジン固有の設定型、JSONの型検証、原子的なファイル置換を採用した。
- ポータブル配布として、設定・辞書・効果音は配置先内のdata、一時音声はcache/audioへ保存する。旧データの探索・移動・変換は行わない。
- 起動をインストール済みパッケージのエントリポイントへ統一し、仮想環境の自動再起動とsys.path操作を削除した。
- Rust拡張をlivevoicebridge._nativeへ移し、型スタブを追加した。protobufは生成物を同梱する。
- 依存宣言をpyproject.tomlへ統合し、Qwen3サービスは独立パッケージにした。CI・開発手順・配布定義を更新した。

## 検証

- Pythonテスト51件。core、依存制約と循環参照、Qt画面操作、全TTSの契約、Qwen3のローカルHTTP通信を含む。
- Python全体のlint・整形・型検査。生成済みprotobuf以外の広範囲な除外は設けていない。
- Rustの整形・clippy・テスト5件。
- メイン画面、設定画面、グラフの描画確認と、設定キャンセル・PiP切替を含む画面操作。
- Windowsの実音声出力経路で短い無音WAVを再生。
- WheelとPyInstallerのWindows実行ファイルをビルド。

上記のビルド検証後、配布定義をポータブルなフォルダ形式へ変更した。現在の出力先は既定で `dist/LiveVoiceBridge/`。配布定義は `packaging/LiveVoiceBridge.spec`。この変更後のビルド・起動確認は行っていない。

## 確認範囲と仕様上の制限

- この環境での実行確認はWindowsで実施した。LinuxのCIと実音声、macOS、4種類すべての実エンジンでの通し確認は別途必要。
- Qwen3のHTTP契約テストは実HTTPサーバーと代替合成器を使用する。GPUモデルの性能を再測定したものではない。
- 設定ファイルと辞書ファイルはそれぞれ原子的に保存する。設定保存後に辞書保存が失敗した場合は、その部分的な結果をエラーとして通知する。
- 停止は保留を破棄し、実行中の合成・再生の終了を待つ。棒読みちゃん側ですでに受け付けた再生はアプリから完了検知しない。
- 旧保存先のconfig.json・dict・soundsおよび既存のモデルデータは変更していない。
