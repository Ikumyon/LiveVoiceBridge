# 第二弾：OS処理とリソース管理

> 過去の設計・実装記録です。現在の仕様は [現行設計](../architecture.md) を参照してください。

2026-10-24〜2026-10-25。正式対象はWindows・Linuxです。

## 境界

- Rustのplatform/windows・platform/linuxがOS固有APIを所有します。
- PyO3はメトリクス、PCMバッファ、音声出力、所有プロセス、配置先を型付きAPIで公開します。
- PythonのcoreにはQt・Rust具象型を入れません。desktopへのOS情報はhostから渡します。
- Qtの画面・ファイル選択・URLを開く共通API、HTTP/gRPC、JSONの保存はPythonに残します。
- 公開型スタブは_native.pyiに定義し、動的なAny辞書APIは廃止しました。

## 取得と履歴

CPU・メモリ・通信量はsysinfo、Windows GPUはDXGI＋PDH、Linux NVIDIAはNVML、AMDは公開sysfsを使います。
LinuxでGPU全体の値を得られない場合、参照できるプロセス分の統計で代用しません。
Intel等も機器として列挙し、未対応の測定値を状態として返します。

数値は約1秒、機器情報は10秒間隔です。カウンターと取得バッファを再利用します。
状態はavailable / warming_up / unsupported / unavailable。正常以外は値を持たせません。
NPUは実測値が得られるまでグラフを生成しません。
60サンプルの履歴はcoreのMetricsStoreが所有し、同じ不変フレームをメイン画面とPiPへ渡します。
監視通知は保留1件にまとめます。非表示のグラフでは描画用の加工を行いません。
ソケットの取得もRustへ移し、Pythonのpsutil依存を削除しました。

## 音声とプロセス

WAVの検証とDSPはRustで実施し、所有するPCMを参照共有します。
DSPは最終サイズを確保前に検査し、不要な中間バッファと係数の再計算を避けます。
再生中・待機中・合成中の予約量を容量予算で管理し、満杯なら合成を待機させます。
1音声は予算の半分か16MiBの小さい方まで。取得中のWAVとDSP作業領域も、この単発上限により制限します。
この設定値はアプリ全体のRSS上限ではありません。

rodioの再生装置をRustのワーカー1系列で管理し、一時音声ファイルや外部再生コマンドを使いません。
効果音は最大16同時。2秒間再生がなければ装置を解放します。
再生失敗は呼び出し結果と上限付きエラーキューで通知します。
WindowsではJob Object、Linuxでは専用プロセスグループを使い、アプリが起動したエンジンと子だけを終了します。
HTTPによる準備確認はPythonが担当します。

## 画面と上限

コメントはQListView＋Model＋Delegateで表示し、行Widgetを生成しません。
コメントとログは最大50ms単位でまとめて反映し、UI待ちのデータにも保持上限を設けます。
進捗通知は最新値を保留1件にまとめます。読み上げと辞書コマンドの順序は変更しません。

アバターは36px相当の表示サイズで共有します。取得は2並列・受付64件・1画像512KiBまで。
デコード後の画像容量をLRUで管理し、コメントモデルは画像キーだけを保持します。
大量のキャッシュ解放時も、モデルの無効化通知をまとめます。

設定「リソース」タブの4組のスライダー＋スピンボックスはDesignerフォームに定義します。
設定はschema_version 2。コメント1000件、ログ2000行、音声32MiB、画像8MiBが初期値です。
OKで適用し、キャンセルでは変更しません。音声上限の引き下げは受け付け済みデータを捨てずに待機します。
上限だけの変更ではセッションを再起動しません。
辞書はSQLiteに保存し、設定画面では全件コピーを作らず変更した行だけを仮保存します。
表のキャッシュは256件×8ブロックまで。DB処理は専用ワーカーで行い、Qtのdata()内では読み込みません。
読み上げ用辞書はRustの不変な圧縮トライです。変更した経路だけを複製し、発話中のスナップショットは共有して維持します。
辞書に変更がなければrevisionを更新しません。教育・忘却は対象単語だけを更新します。
設定画面のメトリクス一覧も機器構成が変わった場合だけ再構築します。

## 配置と検証範囲

保存はEXE配置先内のdataのみ。AppData・OS一時領域・レジストリへの設定保存は行いません。
macOSと新しい自動更新機能は対象外です。独立したQwen3推論サービス本体は変更していません。
外部エンジン自身の保存動作は、そのソフトウェアが管理します。

実施対象はmypy、ruff、cargo check、cargo clippy、Rust整形、UI定義と依存境界の静的確認です。
CIもWindows/Linuxの静的検証へ変更し、LinuxにALSA開発用依存を追加しました。
回帰テストはtestsに用意しましたが、この改修でテストの実行・アプリ起動・配布ビルド・音声再生・負荷計測は行いません。
Windows上の静的検査と、Linux実機での動作確認を区別して報告します。
Rust拡張のバイナリは型チェックでは更新されないため、反映には別途再ビルドが必要です。

別途実行する受入項目は、初回計測・取得失敗・機器切断、遅いUIでの通知滞留、
設定適用とキャンセル、上限引き下げ、音声の順序と容量超過、再生エラー、
所有プロセスだけの終了、繰り返し終了時の解放、異なるカレントディレクトリと読み取り専用配置先です。
実測していない削減率は記載しません。
