# 読み上げ

[仕様書一覧](../README.md)

## コメントから音声まで

1. 履歴・有料イベントの読み上げ設定で対象を判定します。
2. 本文のHTML文字参照を戻し、HTTP/HTTPSのURLを `URL` に置き換え、連続空白を1文字へまとめます。
3. 本文が使用エンジンの最大文字数を超えた場合、先頭から切り詰めて `、以下略` を付けます。
4. 投稿者名・本文・固定テキストの読み上げブロックを順番に連結します。自動の区切り文字は挿入しません。
5. Rustでコメントコマンドを解析し、音声属性の区間・辞書操作・効果音へ分解します。
6. 発話テキストを `。` の直後で分割します。`！`・`？`・改行は文分割の条件ではありません。
7. 各発話の合成直前に辞書を置換し、その後に絵文字を日本語名へ変換します。
8. 合成結果にDSPを適用し、受け付けた順番で再生します。

最大文字数の初期値は全エンジンで50です。`-1` は切り詰めなしを表します。
制限は本文の前処理後、ブロック連結とコマンド解析より前に適用します。
投稿者名や固定文、辞書置換後の文字数を含む最終リクエスト長の制限ではありません。
長いコマンドが途中で切れる場合もあります。

ブロックの種類は `author`・`message`・`text` です。
画面で追加・削除・ドラッグによる並べ替えを行えます。初期構成は本文だけです。
すべて削除すると本文ブロックへ戻します。

## コメントコマンド

属性の指定は、そのコマンドより後の同一コメント内に適用します。
次のコメントには持ち越しません。
数値コマンドは半角括弧と半角数字のみで、符号・小数は受け付けません。
認識できない記述は通常のテキストとして残ります。

| 書式 | 解釈 |
| --- | --- |
| `速度(n)` | 話速を `n / 100` 倍にする |
| `音程(n)` | ピッチを `(n - 100) / 100 × 0.15` にする |
| `音量(n)` | 音量を `n / 100` 倍にする |
| `声(n)` | 使用エンジンの話者IDを指定 |
| `エコー(n)` | エコー値を指定。0は無効 |
| `やまびこ(n)` | やまびこ値を指定。0は無効 |
| `左)` / `左）` | 左だけから再生 |
| `右)` / `右）` | 右だけから再生 |
| `両)` / `両）` | 左右の再生へ戻す |
| `教育(単語=読み)` | 「配信コメント」グループへ登録・更新 |
| `忘却(単語)` | 「配信コメント」グループから削除 |
| `再生(名前)` / `音(名前)` / `sound(名前)` | 効果音を再生 |

例: `こんにちは。速度(120)ここから速く読みます。右)右から聞こえます。`

教育・忘却では登録・削除の通知文を発話計画へ入れ、その後に辞書操作を実行します。
通知文の生成は保存成功を保証しません。保存エラーはログへ通知します。
辞書操作と効果音も読み上げ計画に含むため、履歴などで読み上げ対象外になったコメントや、
キュー超過で拒否された計画からは実行しません。

教育・忘却・効果音の括弧内では、バックスラッシュで次の文字をエスケープできます。
たとえば `教育(a\=b=えーびー)` は単語 `a=b` を登録します。
教育の区切りは最初のエスケープされていない `=` です。

## エンジンの対応

| 項目 | VOICEVOX / COEIROINK | 棒読みちゃん | Qwen3 |
| --- | --- | --- | --- |
| 合成先 | HTTPサーバー | TCP送信 | 管理下のローカルHTTP |
| 再生担当 | 本アプリ | 棒読みちゃん | 本アプリ |
| 話者・音量 | 対応 | 対応 | 対応 |
| 速度・音程 | 対応 | 対応 | 未対応 |
| エコー・やまびこ・定位 | 対応 | 未対応 | 対応 |
| 再生完了の把握 | 可能 | 不可 | 可能 |

使用エンジンが対応しない属性は省略し、エラー通知を出します。
話者IDや値の組合せが外部エンジンで受理されるかは、そのエンジン側でも検証されます。

VOICEVOX・COEIROINKは話者一覧を `GET /speakers`、
クエリ生成を `POST /audio_query`、音声生成を `POST /synthesis` で行います。
抑揚・間長・開始無音・終了無音はエンジン設定からクエリへ渡します。
COEIROINKアダプターも同じ通信実装を使います。

棒読みちゃんはコマンド1のTCPパケットにUTF-8テキストを載せて送ります。
速度・音程・音量の `-1` は外部側の既定値です。
画面の現在テキストは「外部へ送信中」を表し、外部での再生状態を追跡しません。
SEは棒読みちゃん利用時も本アプリで再生するため、外部音声との順序・同期は保証しません。

## キューと容量

セッションごとに合成用1スレッドと再生用1スレッドを持ちます。
再生中に後続発話を合成できますが、同じセッション内の合成は直列です。

- 入力キューはコメント単位の計画を保持します。初期上限100、設定範囲1～10,000です。
- 合成後の出力キューにも同じ件数上限を使います。こちらは発話・効果音単位です。
- 入力が満杯なら新しい計画を拒否し、コメントの表示は続けます。
- セッション制御へ渡すコメント処理待ちは別に1,000件までです。超過時は表示だけを通知します。
- PCM保持容量の初期値は32MiBです。1音声の上限は `min(保持容量 / 2, 16MiB)` です。
- 合成前に1音声分の上限を予約し、完了後に実サイズとの差を解放します。
- 容量不足なら新規合成を待機します。上限を下げても受け付け済みの音声は捨てません。

この容量は保持するPCMと予約の予算です。HTTP応答、デコード時の作業領域、
SE、外部サービスのメモリを含むプロセス全体の上限ではありません。
HTTP音声応答にはPCM上限＋65,536バイトの受信上限も設けています。

停止・設定変更での再構築時は待機キューを破棄します。
実行中の合成リクエストや再生に対する即時割り込みはありません。
個別発話の合成・加工・再生エラーは通知し、後続の処理を続けます。

## 音声加工と出力

本アプリで再生する合成音声は16-bit PCM WAVのモノラルまたはステレオを受け付けます。
デコード・加工後のPCMはRustの不変 `AudioClip` が所有し、複製は共有参照です。
音声の一時WAVや外部再生コマンドは使用しません。

エコーは150msのディレイ1回、やまびこは350ms間隔のディレイ3回です。
減衰率は指定値を100で割り、0.1～0.8に制限します。加算結果は16-bit範囲でクリップします。
両方が有効な場合、ディレイ間隔はエコーの150ms、回数と減衰値はやまびこを使います。
定位指定でモノラルを片側再生する場合はステレオ化し、反対側を無音にします。

Rust/rodioの専用スレッドがOSの既定出力デバイスを必要時に開きます。
再生がなくなって約2秒でデバイスを解放します。
デバイスエラー時は再生を止めて通知し、次の要求で再度デバイスを開きます。

## 効果音

ファイルは `data/sounds/` 直下に配置します。WAV・MP3・FLAC・Vorbisのデコーダーを有効にしています。
指定文字列から最後のファイル名を取り出し、解決後の親がsoundsディレクトリと一致することを確認します。
シンボリックリンクなどで領域外を指すファイルも拒否します。

コメントからのSEは開始後に完了を待たず、後続処理と重ねて再生します。同時SEは最大16件です。
SEには合成音声用のDSPやPCM予算を適用しません。
