# 利用と画面

[仕様書一覧](../README.md)

## 起動と初期準備

配布物をフォルダ単位で展開し、Windowsでは `LiveVoiceBridge.exe`、
Linuxでは `LiveVoiceBridge` を起動します。`_internal/` は実行ファイルと一緒に配置します。
配置先には書き込み権限が必要です。正式配布はx64向けで、Qwenの自動導入もx86_64が対象です。

初回起動時に `data/config.json`、`data/dictionary.db`、`data/sounds/` を準備します。
設定の読み込みや辞書の初期化に失敗した場合は起動エラーを表示します。
データの場所と移行方法は[設定と保存](configuration.md)を参照してください。

1. 設定画面でYouTubeのAPIキーを入力します。
2. 音声エンジンを選び、接続先と話者などを設定します。
3. OKで保存します。
4. メイン画面へ配信URLまたは動画IDを入力し、「開始」を押します。

VOICEVOX・COEIROINK・棒読みちゃんは利用する外部エンジンが必要です。
起動済みのエンジンを使うほか、実行ファイルパスを指定してアプリから起動できます。
COEIROINKは `/speakers`、`/audio_query`、`/synthesis` を提供する接続先を使用します。
Qwenは[アプリ内の準備画面](qwen3.md)で環境とモデルを用意します。

## 配信接続

接続にはAPIキーと配信先の両方が必要です。
入力欄は動画ID、YouTubeのwatch URL、youtu.be短縮URL、live・embed・shorts形式のURLを扱います。
入力値から動画IDを抽出し、YouTube Data APIの `videos` で `activeLiveChatId` を取得します。
ライブ中でない、チャットが無効、動画が存在しないなどの場合は接続エラーになります。

チャット本体はTLSを使用するgRPC StreamListで取得します。
ストリーム切断時はページトークンを引き継いで再接続します。
例外時の待機時間は1秒から倍増し、最大10秒です。応答を受信すると1秒に戻ります。
メッセージIDは直近10,000件を保持して重複を除きます。
配信オフラインの通知を受けた場合はセッションを終了します。

取得対象は通常コメント、Super Chat、Super Sticker、メンバーのマイルストーンチャットです。
これ以外のイベントは一覧・読み上げの対象にしません。

| 設定 | 初期値 | 動作 |
| --- | --- | --- |
| 履歴を読み上げない | 有効 | 最初の応答に含まれるコメントを表示し、読み上げは省略 |
| 有料イベントを読む | 有効 | 無効にすると有料扱いの対象イベントも表示だけにする |

履歴判定は最初のgRPC応答単位です。切断後の再接続で履歴判定をやり直しません。

## メイン画面

| 操作・表示 | 動作 |
| --- | --- |
| 開始 | 入力された配信先を保存し、エンジン準備と配信接続を開始 |
| 停止 | 取得元を閉じ、合成・再生待ちのキューを破棄して終了を待つ |
| テスト送信 | 入力した文を投稿者「テスト」のローカルコメントとして処理 |
| ログクリア | ログとコメント一覧、および表示待ちのログ・コメントを消去 |
| PiPボタン | コメント一覧を独立ウィンドウへ移動、または元のタブへ戻す |
| 設定ボタン | 設定画面を開く。すでに開いていればその画面を前面へ出す |

テスト送信はYouTubeへ投稿しません。未接続でも選択中エンジンで読み上げできます。
開始中・動作中・終了待ちは配信先入力と開始ボタンを無効にします。

停止は即時の消音を保証しません。進行中のHTTP合成やRust側の再生完了を待つ場合があります。
棒読みちゃんへ送信済みの読み上げは、外部アプリ側で管理されます。

一覧は受信した本文を保持し、読み上げ用のURL置換やコマンド除去を反映しません。
表示は約50ms単位でまとめて更新します。投稿時刻ではなく表示処理時の時刻を付けます。
保持上限を超えると古い行から削除します。表示の消去で音声キューや辞書は変更しません。

## 設定の確定

設定画面は編集用の値と辞書ドラフトを持ち、OKで保存・適用します。
キャンセル時は通常の設定変更と辞書編集を破棄し、PiPのプレビューも保存済みの状態に戻します。
Qwenのモデル準備による登録・取得済みファイルは独立して確定するため、親画面のキャンセルでは戻りません。

配信設定、選択中エンジンの設定、使用エンジン、読み上げブロック、
キュー上限が変わると、動作中のセッションを作り直します。待機中の読み上げは引き継ぎません。
表示・リソースだけの変更では作り直しません。

設定JSONを保存した後に辞書を確定します。両方を一つのトランザクションにはしていません。
辞書保存だけが失敗した場合は「設定は保存しましたが辞書の保存に失敗しました」と通知します。

## PiPと監視

PiPは枠なし・最前面のコメントウィンドウです。同じコメント一覧を移すため、別の取得処理は増えません。
移動・サイズ変更ができ、位置・大きさと分離状態を保存します。
閉じるとコメント一覧をメイン画面へ戻します。

背景・ヘッダー・枠線の不透明度、背景色、枠線色を設定できます。
メトリクスは上・下・左・右に配置し、項目ごとに非表示・文字のみ・文字＋グラフを選びます。
分割比率は縦方向・横方向で別に保持します。

監視画面とPiPはCPU、RAM、ネットワーク、YouTube接続数、検出したGPUの同じ履歴を表示します。
約1秒ごとに収集し、各系列は60点を保持します。
YouTube接続数はこのアプリの配信接続の0または1で、視聴者数ではありません。
TTSのアクティブ表示もセッション状態に基づき、外部サーバーの接続実数ではありません。
コメント受信処理キュー欄は現実装では0を渡しており、実際の処理待ち件数は表示していません。
TTSキュー欄は合成前のコメント計画数で、合成済み音声数を含みません。

「計測中」「取得不可」「未対応」を正常な0と区別します。NPUは実測値がない間は表示しません。
GPUの取得範囲はOSとドライバーに依存します。WindowsはDXGI・PDH、
LinuxはAMDのsysfs・NVIDIAのNVMLを使用し、LinuxのIntel GPU使用率は未対応です。

## 更新確認と問題の切り分け

起動時の更新確認は設定で無効にできます。新しい数値バージョンがあれば配布ページを開くか確認します。
ダウンロード・置換は利用者が行います。

| 状況 | 確認箇所 |
| --- | --- |
| 配信へ接続できない | APIキー、動画ID、ライブ状態、チャット有効状態、ログ |
| 外部TTSに接続できない | エンジン起動状態、URL・ポート、指定した実行ファイル |
| COEIROINKでAPIエラー | 接続先が本アプリの使用するVOICEVOX形式APIに対応しているか |
| 表示されるが読まれない | 履歴・有料設定、読み上げキュー超過、Qwen準備状態、エラーログ |
| 音声が容量超過になる | 最大文字数、音声容量、エコー・やまびこによる音声長の増加 |
| Qwenの準備・ロード失敗 | 設定画面の詳細ログ、モデル形式、選択デバイス。再試行・再起動を使用 |
| 辞書の保存競合 | キャンセルして開き直し、配信コメントによる変更を含めて再編集 |
